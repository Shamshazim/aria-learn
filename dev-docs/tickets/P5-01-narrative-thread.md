# P5-01 — `narrative_thread` and the story engine

| **Track** | Backend |

| **Parallel-safe with** | P4-* |
| **Size** | L |

## Why

`master-plan.md` §13 Phase 5: "a continuing story, built from this child's current
interests, that carries the lessons instead of merely framing them." The difference between
a Primer and a worksheet with a truck sticker is that the lesson *is* a beat in a story the
child wants to continue. That needs durable thread state, not a per-turn flourish.

## Scope

### Build
Migration `015` `narrative_thread` + `narrative_beat`; the story engine that opens a thread,
plans the next beat around a due skill, and closes chapters; the beat → move-plan bridge into
the tutor loop; a reviewed set of story frames per band.

### Do not build
No illustrations or voice register (P5-03). No interest sourcing (P5-02 supplies a
`StoryContext` port; this ticket consumes it with a neutral default). No branching-narrative
UI, no "choose your adventure" menu (§14).

## Design

```sql
-- 015_narrative.sql
narrative_thread  id UUID PK, student_id UUID REFERENCES student ON DELETE CASCADE,
                  frame_code VARCHAR(32) NOT NULL,       -- reviewed frame ('lost_robot', 'river_journey')
                  title TEXT NOT NULL, band VARCHAR(16) NOT NULL,
                  characters JSONB NOT NULL,             -- [{ name, role, fromInterestFactId? }]
                  state JSONB NOT NULL,                  -- { chapter, location, openQuestion, inventory }
                  status VARCHAR(16) NOT NULL CHECK (status IN ('active','paused','finished','retired')),
                  started_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL,
                  finished_at TIMESTAMPTZ
narrative_beat    id UUID PK, thread_id UUID REFERENCES narrative_thread ON DELETE CASCADE,
                  session_id UUID REFERENCES session ON DELETE SET NULL,
                  seq INTEGER NOT NULL, skill_code VARCHAR(32) REFERENCES skill(code),
                  summary TEXT NOT NULL, text_hash VARCHAR(128) NOT NULL,
                  outcome VARCHAR(16),                   -- 'solved' | 'helped' | 'skipped'
                  at TIMESTAMPTZ NOT NULL DEFAULT now(), UNIQUE (thread_id, seq)
CREATE UNIQUE INDEX narrative_thread_one_active ON narrative_thread (student_id) WHERE status='active';
```

```
apps/api/src/services/story/
  story.service.ts          openOrResume(studentId) / nextBeat(sessionId, dueSkill) /
                            closeChapter / retire
  frames.data.ts            ≥ 4 reviewed frames per band: premise, recurring characters,
                            chapter arc (5–8 chapters), which skill families fit which beats
  beat-planner.ts           picks a beat slot that can carry `dueSkill` (a counting beat needs
                            countable things; a CVC reading beat needs a decodable sign); if no
                            slot fits, the lesson runs without story this turn (no forcing)
  beat-writer.ts            TEACH model writes the beat: ≤ band sentence limits, ends on the
                            lesson question; gated by P0-18; the *problem* inside the beat is
                            generated by the skill's item generator (P2H-10) and verified by
                            code — the story wraps it, never invents the maths
  story-context.port.ts     StoryContext = { interests: Array<{ label, factId }>, name }
                            default: no interests, name only
  thread-state.ts           pure reducer: (state, beatOutcome) -> state; chapter advances
                            every N solved beats (early 3, middle 4, senior 5)
apps/api/src/repositories/narrative.repository.ts
apps/api/src/ai/prompts/definitions/story-beat.ts
packages/tutor/src/steps/plan-move.ts    accepts an optional `storyBeat` decoration on the
                            MovePlan; policy remains authoritative over the skill
```

Rules:
- **The story never chooses the skill.** Policy/scheduler picks the skill; the story finds a
  beat for it or steps aside. §14: no menus, so the child never picks a story either.
- The arithmetic/reading item inside a beat is produced and verified exactly as outside a
  story. A beat whose item fails the checker is discarded.
- One active thread per child. Finished threads stay readable (parent transcript).
- A thread is `retired` when the child's band changes or the parent asks.
- Beat text hashes are stored to prevent verbatim repeats across sessions.

### Edge cases
- New child, no interests → neutral frame with generic characters; still a story.
- Due skill has no fitting slot → plain lesson turn; `narrative_beat` not written; counter
  for "storyless turns" so a bad frame is visible.
- Child says "I don't like this story" (CHAT/STOP intent) → `paused`; next session offers a
  new frame via `CHECK_IN` (two options, not a menu: "same story or a new one?").
- Model produces a beat with a frightening turn → safety check fails; regenerate with the
  frame's tone constraints; second fail → storyless turn.
- Chapter arc finishes → `END` of session includes the chapter close; next session opens the
  next chapter or, after the last, `finished` and a new frame.
- Session ends mid-beat → beat stays `outcome=null`; resumed next session with a one-line
  recap SAY generated from `summary` (not re-told verbatim).
- Band change mid-thread → `retired`.
- Two sessions race (reconnect) → unique active index makes the second open a no-op.

## Acceptance criteria

- [ ] Migration `015` applies; one active thread per student enforced by the index.
- [ ] `beat-planner` returns "no slot" for an unfitting skill and the turn proceeds without
      story — test.
- [ ] The maths/reading item inside a beat comes from the verified generator, proven by a
      test that injects a wrong-answer item and sees the beat discarded.
- [ ] No beat text repeats verbatim across a thread (hash check test).
- [ ] Pause/resume/retire transitions are covered by reducer tests.
- [ ] Every frame is human-reviewed and recorded in the PR.
- [ ] Story beats pass the P0-18 gate (count assertion).
